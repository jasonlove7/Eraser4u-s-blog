整数溢出是安全领域最常见的漏洞类别之一，
但很多讲解停在"会绕回去"这一层。这篇笔记把它推到底。

## 补码不是一个"约定"，是一个恒等式

对 $w$ 位的无符号数 $x$，补码解释成有符号数的定义是：

$$
B2T_w(x) = -x_{w-1} \cdot 2^{w-1} + \sum_{i=0}^{w-2} x_i \cdot 2^i
$$

也就是说：**只有最高位权重是负的。**

从这条定义出发可以推出一个反复用到的恒等式：

$$
B2T_w(x) = x - x_{w-1} \cdot 2^w
$$

它说明了补码的全部行为：最高位为 0 时结果就是无符号值本身；
为 1 时，相差整整一个 $2^w$。

## 有符号溢出的边界

对 $w$ 位有符号数，取值范围是：

$$
TMin_w = -2^{w-1}, \qquad TMax_w = 2^{w-1} - 1
$$

加法 $x +_w^t y$ 溢出当且仅当：

$$
x > 0,\ y > 0,\ \text{且}\ x + y \geq 2^{w-1}
$$

注意**不能**用结果判断溢出。经典的错误写法：

```c
/* 错误：编译器可以把这个判断整个优化掉 */
if (x + y < x) {
    /* 认为溢出了 */
}
```

原因很微妙：在 C 里，有符号整数溢出是 **未定义行为（UB）**。
编译器有权假设它永远不发生，从而推导出 `x + y >= x` 恒成立，
把这个分支当作死代码删掉。

开启 `-O2` 之后，这段代码在真实的编译器下确实会消失。

## 无符号是"回绕"，不是 UB

无符号运算在 C 里是**定义良好的模运算**：

```c
unsigned int a = UINT_MAX;
a = a + 1;          /* 确定等于 0，不是 UB */
```

这是两者的根本区别：

| | 有符号 | 无符号 |
| --- | --- | --- |
| 溢出语义 | 未定义行为 | 模 $2^w$ 回绕 |
| 编译器可假设 | 永不溢出 | 按模运算 |

这解释了一个看似矛盾的现象：**无符号的溢出更好预测，但更危险** ——
因为它不会触发任何异常，只会安静地给出一个"合法"的错值。

## 一个真实的模式

```c
size_t total = count * sizeof(struct item);
void *p = malloc(total);
if (!p) return -1;

memcpy(p, src, count * sizeof(struct item));   /* 又一次乘法 */
```

如果 `count * sizeof(...)` 在无符号下回绕成一个很小的值，
第一次分配会成功，`memcpy` 则会按**回绕后的长度**拷贝 ——
但调用方以为拷贝了全部数据。

真正的问题往往不在某一次乘法，而在于**同一个表达式被求值了两次，
而两次之间没有任何东西保证结果一致**。

## 检查怎么写才是对的

三种可靠的写法，按推荐程度排序：

```c
/* 1. 用一个能容纳结果的更宽类型 */
size_t total = (size_t)count * sizeof(struct item);
if (count != 0 && total / sizeof(struct item) != count)
    return -1;

/* 2. 编译器内建（GCC / Clang） */
if (__builtin_mul_overflow(count, sizeof(struct item), &total))
    return -1;

/* 3. 先除后乘 —— 但要注意整除的截断 */
if (count > SIZE_MAX / sizeof(struct item))
    return -1;
size_t total = count * sizeof(struct item);
```

第 3 种是最常用的，也是最容易写错的 ——
`SIZE_MAX / sizeof(...)` 的整除下取整，
和 `count * sizeof(...)` 的上取整，边界需要仔细核对。

## 收尾

整数溢出之所以难，不在于数学，而在于**它在 C 里是一个"有时合法、有时未定义"的地带**。
写代码时能依赖的只有一条：不要靠结果反推溢出，
要在做运算之前就用不产生溢出的方式检查。
